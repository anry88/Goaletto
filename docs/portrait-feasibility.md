# Проверка качества генератора портретов · 2026-10-11

Пользователь отклонил PNG-комбинатор r1: вытянутые лица, втянутые рты,
несовместимые шея/одежда. Набор r1 помечен `rejected-visual-quality`, его IDs и
исходники сохранены для воспроизведения. Он не является визуальным стандартом игры.

## Что проверено

[Сравнение A/B/C](../assets/portraits/feasibility-v2/comparison-v01.png):

| --- | --- | --- |
| A: прежняя r1 | Нарушенные пропорции, маленькие губы, шея и воротник не согласованы | Отклонён пользователем |

| C: цельный портрет с цветами формы | Лицо, губы, челюсть, шея и воротник нарисованы согласованно; цвета меняются локально | Предпочтительный кандидат, на просмотр пользователя |

между A/B/C. На [отдельной паре 24/35](../assets/portraits/feasibility-v2/whole-age-v01.png)
у C сохранена узнаваемость при офлайн-редактировании возраста.

## Причины прежнего результата

Importer r1 применял `resize(width, height)` независимо к каждому alpha bbox.
Это меняло соотношение сторон. Позиции глаз/носа/рта и шеи/воротника были заданы
без общего анатомического эталона; возрастные линии и skin edges не исправляют
несогласованные объём и контуры. Количество сочетаний не подтверждает качество.

B использует `ImageOps.contain` — один масштаб по обеим осям, новое положение одежды
и больший естественный объём губ. Он всё ещё не достигает цельного рисунка.
По этой пробе нельзя объявить все модульные генераторы невозможными: отдельно
спроектированные совместимые слои, единые landmarks и визуальная матрица требуют
своего художественного производства. Простое расширение текущего AI-atlas этого не решает.

## Практический путь для текущего Dugout

Подготовить офлайн библиотеку **цельных персонажей** с согласованными возрастными
вариантами; runtime выбирает сохранённый appearance ID, возрастный вариант и
перекрашивает проверенные области одежды в два цвета клуба. Голова/шея/воротник
остаются цельной анатомией. Для персонала нужен отдельный мужской банк.

Не требуется генерация по сети при каждом появлении футболиста. Один комплект
внешности можно назначать нескольким игровым людям, сохраняя назначение в БД.
Но это конечная библиотека: если требовать уникальное лицо каждому человеку,
нужно изготовить больше уникальных внешностей. Seed выбирает готовую внешность,
а не создаёт новую анатомию. В этой пробе пока **одна** внешность с двумя возрастами,
не большая библиотека и не рабочая выдача персонажей в игре.

Возраст +1 за сезон — число в домене; иллюстрация меняется при переходе возрастной
стадии. Все варианты одной identity готовятся и проверяются заранее, история
использует прежний вариант. Не генерировать новый случайный портрет каждый сезон.

## Результаты и воспроизведение

Все файлы — [feasibility-v2](../assets/portraits/feasibility-v2/README.md):
исходный цельный master, правка короткой шеи, вариант35, полные prompts.
Созданы встроенным Imagegen. [Три формы одного лица](../assets/portraits/feasibility-v2/whole-kit-v01.png)
и A/B/C собраны Python/Pillow, без сети. Прозрачность исходников RGBA сохранена.

```bash
python scripts/check_portrait_feasibility.py
```

Выводит 512px образцы и 96px проверки, матрицу формы и два возраста.
Программа проверяет неизменность пикселей в явно заданных областях головы/подбородка
при смене цветов. Почти прозрачный цветовой шум исключён из tint; semantic ROI
ограничивает перекраску одеждой. ROI этой пробы измерен для конкретного master;
production потребует своих явных material masks для каждого approved master,
чтобы цвет глаз/волос не менялся из-за совпадения с техническими цветами.

Численные проверки подтверждают отсутствие растяжения/смены лица от формы и
повторяемость. Они не заменяют визуальную оценку, особенно анатомии и возраста.
Статус AND-44: In Progress. Новое качество ещё не утверждено пользователем.
Персонал, большое разнообразие, все возрастные стадии, durable cache и интеграция
с ботом этим экспериментом не проверены. Никакого массового производства сейчас нет.
