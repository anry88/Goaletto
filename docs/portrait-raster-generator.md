# Автогенератор иллюстрированных портретов

2026-10-11: рабочий локальный Python/Pillow-пилот в направлении Dugout.
Он собирает новые изображения из прозрачных деталей; нейросеть при сборке не вызывается.
Большой каталог и интеграция с карточками/БД остаются задачей AND-44/AND-45/AND-48.

## Два отдельных мужских банка

[Каталог](../assets/portraits/raster-pilot/manifest-v1.json): по 16 деталей на банк,
32 RGBA PNG на общей сетке 512×512. В каждом: 3 основы головы с ушами/шеей,
3 причёски, 2 пары глаз с бровями, 2 носа, 2 рта, 2 одежды, 2 возрастных overlays.
ID имеет вид `dugout-r1/players/nose-straight`; staff использует свой namespace.
Старый SVG manifest/IDs сохранены. Женский комплект сейчас не производится.

Детали изготовлены встроенным Imagegen **как отдельные части**, не вырезаны
из листов готовых игроков. Сырой atlas, prompts, измеренные crop regions и импорт
сохранены. Атласы не дали точную математическую сетку, поэтому importer использует
явные проверенные области и общие anchors. Носы игроков уточнены отдельно:
прозрачные контуры вместо заливки светлой кожи.

Голова → одежда → возраст → глаза → нос → рот → волосы. Одежда закрывает нижнюю
часть шеи, а возрастные линии ограничены alpha головы и не рисуются на фоне.
Небольшие тёплые skin edges глаз/рта адаптируются к тону головы; этот технический
приём требует дальнейшего визуального контроля, особенно для тёмных оттенков.

## Постоянная личность, отдельный контекст

`RasterRecipe` хранит asset_version, bank, seed и конкретные IDs головы/глаз/носа/
рта/волос/одежды. SHA-256 выбирает части независимо по ключам, без глобального random.
Сохранить рецепт при создании человека и затем рендерить его; не создавать новый
seed при открытии карточки, изменении цвета формы или повышении в лигу.

Age и два цвета формы **не входят в неизменяемую личность**. Игроки 17–27 рендерятся
без линий, 28–31 с тонкими, 32–38 с более зрелыми; персонал до45 без добавочных линий,
45–54 с тонкими, 55+ с более выраженными. Пилот меняет overlays, но ещё не содержит
индивидуальной эволюции волос/геометрии челюсти. Это остаётся в production-каталоге.
Возрастное число передаёт приложение; renderer не увеличивает возраст и не решает пенсию.

Одежда обеих банков имеет две технические цветовые области: magenta — основной
цвет, cyan — дополнительный. Runtime заменяет их на цвета формы текущего клуба,
сохраняя контуры, тени и alpha. Фиксированные бордовый/мох остаются оформлением,
но не заставляют все клубы носить одну форму. Смена формы не меняет лицо.

Будущий PNG/Telegram file_id cache должен включать сериализованный рецепт,
asset version, age stage, оба цвета/версию формы, размер и фон. Исторический snapshot
сохраняет старый возраст и форму; текущая карточка использует текущие цвета.
Автоматического хранения персонажей в БД и Telegram file_id cache пока нет.

## Запуск

```bash
python -m pip install '.[art]'
python -m goaletto.portraits.raster_cli --seed footballer-001 --bank players --age 24 \
  --kit-primary '#743D42' --kit-secondary '#F2E9D8' \
  --output work/player.png --recipe-output work/player.json
python -m goaletto.portraits.raster_cli --recipe work/player.json --age 35 \
  --kit-primary '#2B435C' --kit-secondary '#DFA642' --output work/same-player.png
python -m goaletto.portraits.raster_cli --seed coach-001 --bank staff --age 55 \
  --kit-primary '#6B755D' --kit-secondary '#F2E9D8' --output work/coach.png
```

`--size` принимает 96/256/512; `--transparent` оставляет фон прозрачным.
После установки также доступен entrypoint `goaletto-raster-portraits`.
CLI не обращается к сети, aiogram, PostgreSQL или Imagegen.

```bash
python scripts/pack_raster_portraits.py
python scripts/render_raster_portrait_preview.py
```

Первый импортирует purpose-made atlases, второй сохраняет сборки и рецепты.
Не запускать importer поверх новой несовместимой графики под старой версией:
изменённым компонентам/anchors нужен новый namespace/version, старые файлы сохранять.

Есть 72 рецепта головы/глаз/носа/рта/волос на банк до одежды; видимые отличия
и убедительность ниже формального количества сочетаний. Массовой уникальности
пока нет: нужны более различимые силуэты/носы/глаза, выверенные посадки, переходы
возраста, оттенки кожи и аксессуары персонала. Некоторым сборкам ещё нужно убрать
видимость отдельных наклеенных деталей и достичь качества исходного концепта.

Проверки: повторяемые pixels/recipe, оба цвета без изменения лица, alpha/ink,
размеры, все детали в своём банке, запрет чужих IDs/путей, границы возраста и версия.
Эти тесты подтверждают сборку, не художественное качество; AND-44 остаётся In Progress.
