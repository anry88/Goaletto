# Английские названия клубов · AND-185

Уточнение владельца 2026-10-27: новые комплекты получают понятные английские
названия из расширенного пула. В существующем мире обновляются только клубы,
у которых **никогда не было владельца**, включая завершённые периоды владения.
Пользовательские и все когда-либо принадлежавшие менеджерам клубы сохраняются.

`english-clubs-v1` фиксирует 200 английских топонимов и 16 футбольных окончаний:
3 200 вариантов, например Oakbridge United, Silverbrook Rovers, Northgate Eagles.
Одинаковые названия используются в RU/EN; страна клуба не ограничивает каталог.
Это косметика без игровых бонусов. Менеджер по-прежнему может переименовать клуб
по действующим правилам; подсказка перед получением клуба сохранена.

## Новые комплекты

Initializer читает названия всех существующих клубов под общим allocation lock.
Сначала выбираются неиспользованные варианты, затем самые редкие; внутри одного
комплекта все 50 различаются даже при неравномерной загрузке каталога. При пустом
мире пул покрывает 64 комплекта до первого повтора. Пользовательские названия
тоже учитываются. Сравнение игнорирует регистр/повторные пробелы и использует
прежнюю латинскую проекцию кириллицы. Пользовательские дубликаты не запрещаются.

Порядок детерминирован по ключу комплекта отдельным SHA256, без расходования
игрового RNG. Старый shuffle 50 названий сохранён до косметической подстановки:
составы, skills, пенсионные draw, UUID, kit и tie-break остаются прежними.
Имена сохраняются в Club, а `club_naming_policy` — в новом world receipt/hash.
Старый receipt без этого поля проверяется прежним fingerprint и возвращает
существующий мир; клубы/люди заново не создаются. `club_naming_policy=None`
воспроизводит старые каталоги и их fingerprints. Демонстрационный golden replay
продолжает явно использовать прежние названия.

## Уже созданные клубы

Миграция 0061 добавляет immutable `default_club_name_receipts` с исходным/новым
названием, club UUID, версией и временем. Сама миграция названия не меняет.
Операторская команда по умолчанию показывает план:

```sh
python -m goaletto.application.default_club_names
python -m goaletto.application.default_club_names --apply
```

Применение использует тот же allocation lock, что claim/rename/world generation,
и блокирует актуальные строки Club. Наличие любого OwnershipPeriod или owner
projection исключает клуб. Названия нового каталога и уже обработанные клубы
пропускаются. Текущие названия исключённых клубов резервируются перед подбором.
Запись Club.name и квитанции атомарна; rollback отменяет обе, retry ничего не
переименовывает. Записи о переименовании защищены от UPDATE/DELETE в PostgreSQL.

Составы, люди, ownership, бюджет, страна, seed receipts и история не меняются.
Frozen match documents продолжают показывать сохранённые прежние названия;
checkpoint/hash не переписываются. Production не сбрасывается.

## Проверки

- Пул: допустимая ASCII-латиница, 3 200 разных названий до 30 символов;
  64 комплекта без повторов, нормализация, исчерпание и неравномерная загрузка.
- Старые legacy/international/nationality миры совпали с fingerprint и полным
  hash содержимого, снятыми до изменений; новые меняют только названия.
- PostgreSQL: preview/rollback/retry, защита нынешних/бывших владельцев и legacy
  owner projection, immutable аудит, два конкурентных initializer без повторов,
  настоящий retry старого receipt и прежний UI переименования.
- Ruff/format/mypy, offline SQL, online upgrade и `alembic check`.

Локальная приёмка 2026-10-27: 1 306 unit/offline сценариев прошли (один HTTP-тест
повторён с разрешённым loopback-сокетом), четыре последовательных PG-сценария
на единственной Goaletto development DB. Mypy — 233 модуля, ruff/format — 665 файлов.
Миграция применена, `alembic check` не нашёл расхождений.
