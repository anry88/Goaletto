# Пакетная проверка матчей офлайн · AND-71 (офлайн-часть)

`scripts/validate_match_batches.py` — bounded CLI для пакетных проверок матчей
на существующем движке `regulation-v2` / `match-policy-v2`.
Без PostgreSQL, Telegram, загрузки PNG и изменения игрового баланса.
Движок, application-адаптеры и `scripts/simulate_economy_season.py` не меняются;
экономический прогон 450 матчей не дублируется.

## Запуск

```bash
python scripts/validate_match_batches.py --seed 7 --matches 8 \
  --output work/match-batch-validation
python scripts/validate_match_batches.py --seeds 7,8,9 \
  --scenarios baseline,home_swap,scripted_commands --csv \
  --output work/match-batch-validation
```

Параметры: `--seed` (база, по умолчанию 7), `--seeds` (явный список, перекрывает
`--seed`/`--matches`), `--matches` (матчей на сценарий, по умолчанию 8),
`--scenarios` (подмножество), `--output` (stem отчёта), `--csv` (дополнительный
CSV построчно по матчам), `--max-matches` (бюджет, по умолчанию 2000;
превышение — ошибка, а не молчаливое усечение).

Выход: `<stem>.json` (машиночитаемый отчёт), `<stem>.md` (сводка для человека),
опционально `<stem>.csv`. Для симуляции `datetime.now` не используется; в отчёте
нет wall-clock меток времени — только замер длительности прогона. Большие
результаты лежат в `work/` и не коммитятся в Git.

Средний пакет (12 сценариев × 8 матчей = 96 матчей плюс replay и checkpoint
рестарты): ~4,5 с офлайн, JSON ~227 КБ, Markdown ~40 КБ.

## Сценарии

Все сценарии используют фиксированный мир `match-batch-validation` (seed 0),
сопоставимые baseline-составы и явные сиды матчей. Пары клубов детерминированно
ротируются по лигам; `home_swap` повторяет пары `baseline` с обменом хозяев.

| Сценарий | Что проверяет |
|---|---|
| `baseline` | Фиксированная сохранённая заявка, без live-команд |
| `home_swap` | Те же пары со сменой домашнего поля (парное сравнение) |
| `saved_lineup_no_manager` | Без менеджера: тактика/менталитет неизменны, принятых команд нет |
| `short_squad_11` | 11 выбранных игроков, пустая скамейка |
| `bench_14` | 14 участников и короткая скамейка |
| `unavailable_bench` | Недоступный запасной никогда не выходит на поле |
| `last_season_starter` | Игрок с меткой последнего сезона играет (запрет торговли ≠ запрет матча) |
| `roster_25_snapshot_20` | Ростер клуба 25, участников snapshot — 20 |
| `scripted_commands` | Скриптованные замены/тактика/менталитет/инструкции, лимиты 5/3/3/3, halftime-окно |
| `injury_storm` | Форсированные травмы: injury-only автозамены, пустые резервы |
| `dismissal_red_storm` | Форсированные прямые удаления вплоть до abandoned |
| `second_yellow_storm` | Вторые жёлтые без прямых красных |

Политики штормов (`injury_bps/direct_red_bps/yellow_bps=10000`, остальное 0)
и спокойная политика скриптованных матчей — явные параметры сценариев,
записанные в отчёт. Коэффициенты движка, aging/retirement и экономика не меняются.

Checkpoint/restart проверяется на сценариях `baseline` и `scripted_commands`
на границах 1/14/15/16/23/29: состояние гоняется через codec (`state_json` →
`restore_state`) и доигрывается; сравниваются финальный hash, оставшиеся события,
счётчики лимитов и фаза. Replay одинаковых входов сверяется по hash и порядку
event ID для каждого матча.

## Агрегаты и инварианты

Агрегаты по сценариям: голы home/away, ничьи, удары и в створ, карточки/травмы/
автозамены, использованные лимиты, доля abandoned, квантили суммарных голов,
парные сравнения сценариев на общих сидах.

Correctness assertions (падение → exit 1): 30 тиков у завершённых матчей,
abandoned отдельно (причина, тик < 30, состояние заморожено), детерминизм replay,
identity checkpoint-рестартов, лимиты, невозврат удалённых/снятых, консистентность
`on_target = голы + сейвы соперника`, уникальность event ID, ожидаемые reject
скриптованных лимитов, игра last-season, недопуск недоступного в старт.

Статистические наблюдения отделены от assertions: на маленькой выборке частота
голов не требуется, корреляции не выдаются за эффект тактики.

## Детерминизм

Содержательная часть отчёта (метаданные, агрегаты, матчи, assertions,
observations) хэшируется в `content_hash` (SHA-256 канонического JSON).
Одинаковый seed даёт одинаковый `content_hash`; длительность и размеры файлов
в него не входят. Smoke-тест `tests/unit/test_match_batch_validation.py`
проверяет это за ~3 с.

## Границы

Это офлайн-проверка движка и чувствительности, а не нагрузочный прогон AND-71:
нет PostgreSQL, production-worker, live-тайминга 33 минут, Telegram-доставки и
конкурентных транзакций. PG/native проверки выполняет Codex последовательно
после сохранения мира.

Приёмка Codex: abandoned считается отдельно и не даёт официальные wins/draws;
полные event payloads и command outcomes входят в replay-сравнение. Пустой список
сценариев, повторные seeds/scenarios и чрезмерное число seeds отвергаются до симуляции.
