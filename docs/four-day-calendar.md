# Четырёхдневный календарь · AND-118 / AND-121

Реализован 2026-10-15. По последнему решению пользователя: 18 игровых циклов
по 4 UTC-дня (72 дня) и 2 цикла межсезонья (8 дней). Полный оборот — 80 дней,
то есть 20 игровых недель. Межсезонное трансферное окно открыто все 8 дней.

Фазы: кубок → кубки чемпионов → свободный день → лига. У сезона хранится
UTC-дата начала цикла; первый тур лиги приходится на её четвёртый день.
Зарплаты и периодические доходы/расходы используют 345600 секунд.
Первый неполный период от создания мира до ближайшей границы оплачивается
пропорционально. Следующие счета идут каждые 4 дня, в том числе в межсезонье.
Числовой баланс и дешёвое содержание/дорогие задания скаута ещё требуют AND-105/116.

Создание мира сохраняет 450 структурных fixture_plans: пары, тур, UTC-день.
Точные старты, immutable решения предпочтений и 34 задания на матч появляются
только при входе в интервал [сейчас, сейчас + 10 суток). Почасовой durable
calendar.materialize расширяет горизонт. Уже объявленные встречи остаются
фиксированными после изменения времени, владельца и повторного запуска worker.
Для ещё не объявленных используется актуальный IANA-пояс и местное время.

Неполные кубковые пары могут храниться условными слотами. Они не превращаются
в лиговые матчи: сетки/двухматчевый runtime/нейтральный финал — AND-123–126.
Старт проверяет пересечение активных матчей; планировщик резервирует два часа
в расписании. [Межматчевая энергия AND-127](player-recovery.md) теперь реализована.

Пропущенное предматчевое окно не запускает пачку старых тиков. Необъявленный
план получает blocked_reason; оператор может перенести его на будущий UTC-день
той же фазы. По умолчанию команда откатывает предпросмотр, --apply сохраняет:

```bash
python -m goaletto.application.calendar_cli --season-id UUID
python -m goaletto.application.calendar_cli --season-id UUID \
  --recover-plan UUID --day 2026-11-02 --apply
```

Тренировочный план хранится по клубу и UTC-дате, завершается в следующую полночь.
Любой назначенный матч блокирует тренировку; объявление обязательного матча
отменяет ещё не применённый план. Дневной рост и вероятности уменьшены в 7 раз
от недельной базы. Выбор будущей даты, специалисты и окончательный сезонный
баланс остаются AND-129/110/111.

Rollover ждёт конца 72-го дня и все 450 результатов/обязательные планы. Он
создаёт следующие 450 планов и три сезонные задачи, затем горизонт наполняет
ближайшие матчи. При позднем завершении новая граница сдвигается целыми циклами.
Межкомплектный одновременный переход — отдельный AND-119; текущий переход внутри
комплекта сохранён. Новые комплекты получают полный сезон с epoch следующего UTC-дня, а не
остаток чужого сезона. Синхронизация совместимых границ для общих переходов
остаётся AND-119. Нельзя считать календарные задачи реализацией всех кубков.

Старый тестовый мир сброшен по прямому указанию пользователя: реальных игроков
в нём не было. Миграция 0024 применяется к чистой схеме; перенос и совместимость
со старым семидневным игровым состоянием намеренно не реализованы.

Проверки: ruff, форматирование, mypy (129 модулей), 648 unit-тестов и 32 разных
PostgreSQL-сценария с повтором исправленных проверок. Проверены полный rollover,
rollback/retry, конкурентная материализация, строгая граница 10 дней, DST,
неподвижность объявленных встреч, неполный первый счёт, ежедневная тренировка,
рынок и историческая вместимость стадиона. Миграции отрендерены и применены
к чистой единственной Goaletto DB; alembic check не обнаружил расхождений.
