# Стадион и посещаемость · AND-63

С 2026-10-25 действует [обновление AND-177](supporters-and-attendance.md):
растущая за успехи аудитория, разные турниры/стадии, прогноз своего следующего
матча, исторические интервалы мерча и сохранение закреплённой посещаемости.
Описание V1 и прежняя калибровка ниже сохранены как история первой реализации.

`/stadium` и кнопка стадиона показывают текущий уровень, фанбазу, содержание,
свободные деньги, ближайший домашний матч, прогноз зрителей/билетов, стоимость и срок
следующего расширения. При свободных местах экран объясняет необходимость роста
спроса; расширение не создаёт зрителей. В RU/EN доступны обновление, финансы и клуб.

Уровни GDD: 5K / 10K / 20K / 35K / 50K, переходы за 300K / 800K / 2M / 5M.
Расширяется только на один уровень. Начальный срок — семь календарных дней, явный
параметр первой реализации, поскольку GDD не задаёт длительность. Стоимость списывается
при заказе через ledger, уровень меняется после durable stadium.complete job.
До завершения доступны прежние трибуны. Повтор старого operation не заказывает новое
расширение даже после завершения; quote привязан к ownership и from_capacity, stale
quote/строящийся стадион/max level/долг/занятые ставками деньги блокируют расход.

StadiumExpansion хранит неизменяемую оплаченную quote и дату фактического завершения.
Один queued row на клуб, один job и money operation на заказ. Последующая смена
менеджера или истечение владения не отменяют уже оплаченное имущество клуба;
completion не продлевает владение. Недельное содержание делится по интервалам
фактической вместимости. Опоздавший invoice не берёт текущую вместимость за прошлую
неделю. Пересечение в секундах и начисление округляются вверх; суммы остаются integer.
История вместимости восстановима из исходной from_capacity и completed expansions.

## Прежний спрос stadium-demand-v1

Детерминированно, без дополнительных случайных draws:

`bps = clamp(8000 + (11-place)×400 + (5-tier)×1000 + recent_form, 5000, 20000)`.

Recent form — до пяти результатов этой лиги/сезона, законченных до расчёта:
win +400, draw 0, loss −400 bps каждый. Attendance = min(capacity,
floor(supporters×bps/10000)). Базовый спрос 80%, место добавляет 4–40%, tier 0–40%,
форма −20..+20%. Это стартовая калибровка, не утверждённый итоговый баланс.
Фанбаза не увеличивается автоматически этим коэффициентом: учитывается спрос на
конкретный матч. Пустая арена не даёт бонуса.

На lineup lock до kickoff runtime фиксирует HomeCrowd в starting_snapshot и
immutable MatchCrowd basis: фанбаза, вместимость, tier/place, последние results,
коэффициент и итоговые зрители. Каждый матч тура использует известную на тот момент
таблицу; будущие результаты не входят. Дальнейшее расширение/пересмотр прогноза не
меняют текущий матч. Engine получает тот же HomeCrowd для временной морали, а
финансовый ticket receipt использует его же после finish. Replay/retry не пересчитывает
спрос. Старые матчи и старые crowd snapshots остаются прежними, без заднего начисления.

[Полный сезон из 450 матчей](economy-season-validation.md) проверяет комплект из пяти лиг, все 18 туров, sponsor/merch/wages/18 invoices/9 home tickets/one final prize.
При исходной фанбазе 2,500 мест 5K хватает: расширение не улучшает билетный поток.
Это видно менеджеру до оплаты. [Стресс стартового капитала](economy-calculation.md)
покрывает также пустые трибуны и дорогой штаб.

Goaletto development DB: два параллельных заказа → одна оплата/job, repeat до/после
completion, stale ownership/capacity, reserve protection, полный rollback заказа,
completion после expiry без продления ownership, pinned crowd при смене вместимости,
исторический invoice и смешанная неделя 3,500 после 5K→10K в середине недели,

income один раз с MatchResult. Native Telegram проверяет текущий экран и навигацию.
