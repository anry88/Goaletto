# Промпты внешним агентам · 13 октября 2026

Каждый файл ниже — самостоятельный промпт: копировать целиком одному исполнителю.
Общие инструкции уже включены; отдельный контекст переписки не требуется.
Промпты подготовлены по актуальному коду и Linear, а не по старому списку A–F.
Пакеты A–D выполнены внешними агентами и приняты Codex с исправлениями;
[отчёт проверки](../../agent-wave3-review.md). Пакет E пока не начат.

## Первая волна: независимые файлы

| Пакет | Промпт | Результат | Связь с Linear |
|---|---|---|---|
| A | [Диагностика](01-diagnostics.md) | Актуальный read-only health для jobs, recovery, рынка и резервов | Части AND-70/69 |
| B | [Аналитика](02-analytics-validation.md) | Точные fixtures, n/N и проверка текущих SQL | Часть AND-82 |
| C | [Офлайн-прогоны](03-offline-match-validation.md) | CLI пакетных матчей, checkpoint/replay и статистика | Часть AND-71 |

A–D можно выполнять параллельно в отдельных ветках/checkout от одного свежего
origin/main. Их списки файлов не пересекаются. Ни один не меняет игровую схему,
worker/dispatcher, экономику или баланс движка. PG fixture — это логически
изолированный набор данных на одной Goaletto DB при приёмке, не новая test DB.
Если исполнителей меньше, приоритет: A → C → B → D.

## Вторая волна: игровая функция

[E · Добровольные отзывы](05-voluntary-feedback.md) — часть AND-78.
Начать после принятия первой волны от новой origin/main. Это единственный владелец
новых feedback models/migration и узкого UI wiring в своей волне. Ручной отзыв
после первого результата; автоматические кампании пока не входят в подпакет.

## Что делает Codex при приёмке

1. Проверяет base SHA и diff, соблюдение границ, реальные assertions и список
   passed/skipped. Не заменяет неподтверждённые правила своим предположением.
2. Для A/B/E последовательно выполняет релевантные PG-проверки на единственной
   Goaletto development DB, предварительно проверив target и сохранив мир.
   После появления реальных пользователей разрешение на development reset не действует.
3. Проверяет read-only/truncation для A, точные n/N для B, reproducibility для C,
   настоящий dump и согласованный restore drill для D, ownership/dedupe/privacy и
   RU/EN/native Telegram для E. Изменения схемы E: offline + online migrations/check.
4. Сводит принятую работу в main, публикует main, закрывает только выполненные
   подпакеты. Родительская задача не закрывается автоматически.

Граница «Codex проверяет» означает: агент сдаёт работающий bounded подпакет,
а Codex делает review, общие проверки и ограниченную интеграцию. Это не обещание
принимать код без исправлений. При расхождении интерфейсов нужен integration.patch,
а не две альтернативные версии архитектуры.

## Что не выдавать по этим промптам

- Уже готовые тренировки, финансы, стадион, рынок, RU/EN, заявки и основные отчёты.
- Полный rollover AND-57: общая транзакция календаря, возраста, рынка, зарплат,
  молодёжи и уникальных appearance требует центральной интеграции.
- Персонал/вторая карьера AND-61/83, полный AND-64, академия AND-62, Stars AND-67,
  кубок AND-65: часть правил ещё требует решений; агент не выбирает их молча.
- AND-84 (визуальный комплект формы): в самой задаче зафиксировано «завести,
  не выполнять сразу»; в эту волну не включена.
- Портреты/генерация изображений, запуск production и изменения соседних сервисов.
- Массовые feedback-рассылки/эксперименты до instrumented eligible opportunities.
