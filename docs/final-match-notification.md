# Финальный результат · AND-92

По окончании игры runtime ставит отдельный `match_result` каждому действующему
владельцу её клубов. Это не требует открытия матча или пользовательской сессии.
Настройки напоминаний не подавляют результаты. Бот-клубам сообщения не отправляются;
ownership/bot-availability guards по-прежнему проверяются перед сетью.

Финальный результат отправляется новым Telegram-сообщением через durable sender.
Он не использует live board lease/key или edit старого табло. Повторный job
подавляется прежним уникальным dedupe key; повтор sender подавляется terminal
receipt. Неустранимый crash после send до commit остаётся at-least-once delivery.
Pending legacy result rows нормализуются на отдельную доставку при claim.

Причина дефекта первого тура: `match_result` использовал общий board key и выполнял
edit сообщения live-табло. Оба результата имели outcome `edited`, что не создавало
нового уведомления. `sent` в БД подтверждал успешный Telegram edit, а не прочтение
или заметность финала. Состояние и расчёт результатов были корректны.

`/match` выбирает активный/приостановленный матч, затем последний завершённый,
затем ближайший scheduled. После финального свистка счёт и лента остаются видимыми,
есть действующая кнопка полного отчёта `hx:m:`. Будущая встреча показана отдельно
с датой и временем UTC. Старые live-кнопки обновляют экран на финал без применения
команды к закрытому матчу.

Проверки: 404 unit/offline, Ruff/format и mypy; реальное чтение `/match` обоих
аккаунтов при наличии будущих fixtures, без записей с rollback. Destructive
integration fixtures не запускались, 25 результатов и таблицы сохраняются.

Для первого тура отдельная однократная постановка восстановленных финальных
уведомлений использует deterministic stage `finished:standalone-v2`. Старые попытки
и результат-табло не переписываются; sender доставляет новые строки штатно.
