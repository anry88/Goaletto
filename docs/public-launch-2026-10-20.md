калибровка используют только отдельный локальный disposable Goaletto.

Защита включается **до открытия регистрации**, даже до первого внешнего игрока
или платежа. `data_protection.protected_at` нельзя обнулить/изменить/удалить;
существующие PostgreSQL triggers запрещают TRUNCATE основных игровых и платёжных
таблиц и снятие guard через downgrade. Это защита от прикладного сброса; права
администратора PostgreSQL/хоста не являются физически необратимым механизмом.
Обход защиты административными средствами также запрещён правилами проекта.

Проверка состояния (только чтение):

```bash
python -m goaletto.application.data_protection_cli
```

Одностороннее включение в production Goaletto:

```bash
python -m goaletto.application.data_protection_cli --seal
```

Команда не имеет операции отключения и повторно сохраняет исходную дату защиты.
Без `--seal` ничего не меняет; запись разрешена только для production и БД `goaletto`.
Приватный `internal_telegram_ids` остаётся для корректной аналитики, но больше
не ограничивает регистрацию. Автоматический feedback остаётся выключенным.
PGDATA остаётся на D, overlay мониторинга и backup на Mac сохраняются.
