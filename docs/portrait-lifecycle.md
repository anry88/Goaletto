# Возрастные и карьерные портреты Dugout

Цельные иллюстрации одного человека, а не комбинации отдельных глаз/носов/ртов.
Решение 2026-10-13: пул из 1 000 футбольных и 80 исходных кадровых иллюстраций
можно использовать повторно для новых людей. Собственный person ID, имя и история
не зависят от номера иллюстрации. Назначенное лицо человека сохраняется при старении
и второй карьере. Старый запрет повторного назначения отменён; новые картинки пока
не нужны. Первый существующий комплект сохраняет свои 1 000 разных портретов.

## Визуальные группы

| Игрок | Персонал |
| --- | --- |
| 17–21: юный | 32–44: начало второй карьеры / сотрудник |
| 22–27: взрослый | 45–59: опытный сотрудник |
| 28–31: зрелый | 60–70: старший сотрудник |
| 32–38: ветеран | — |

Диапазоны относятся к выбору иллюстрации. Они не вводят новый возраст найма,
обучение или пенсионную вероятность. Все персонажи мужские на текущем этапе.
Возраст игрока растёт на год за сезон по [правилам](player-lifecycle.md), но портрет
меняется только на границах групп. 32–38 не означает пожилое лицо или обязательную
седину. Метка «Последний сезон» остаётся отдельным текстом в карточке.

Каждому игроку готовятся четыре футбольные и три кадровые версии того же лица.
Исходному сотруднику — три кадровые версии. Исторические изображения и variant IDs
не переписываются. Кадровый профиль бывшего игрока принадлежит тому же person; переиспользование
иллюстрации другим человеком не переносит чужую историю.

## Локальное использование

`WholePortraitRecipe` закрепляет catalog version, identity ID и variant ID.
`recipe_for_age(recipe, bank="staff", age=52)` выбирает кадровую иллюстрацию
этого же человека, сохраняя identity. Функция не решает, станет ли игрок сотрудником,
не начисляет возраст и не выполняет межсезонье. Эти правила ещё предстоит реализовать.
Отсутствующий диапазон, неизвестная версия или чужая identity дают ошибку;
подмена случайным лицом запрещена. При сохранении исторической карточки закреплять
её variant ID, а не каждый раз пересчитывать внешность по текущему возрасту.

`render_whole` меняет только область одежды через явную маску. Основной PNG —
256×256 с alpha; миниатюра — 96×96. Технические magenta/cyan не являются цветами
игровой формы: они обозначают две перекрашиваемые области. Галерея показывает
готовые бордовые/кремовые превью. Runtime не обращается к Imagegen или иной сети.

```bash
python scripts/render_whole_portrait.py --variant p0001-player18 \
  --bank players --age 30 --size 96 --output work/player30.png
python scripts/render_whole_portrait.py --variant p0001-player18 \
  --bank staff --age 52 --primary '#315B49' --secondary '#E2BF57' \
  --output work/former-player52.png
```

## Производство и проверка

[Расширение и prompts](../assets/portraits/whole-v2/lifecycle-v1/README.md),
[возрастная галерея](../assets/portraits/whole-v2/lifecycle-v1/index.html).
План: 362 листа по 20 цельных портретов, 7 240 дополнительных вариантов,
1 080 внешностей. Фактический статус/объём — в import-report.json и manifest.json;
`partial-generation` нельзя выдавать за завершённый каталог.

На 2026-10-12 сохранено 289 листов / 5 780 вариантов: 780 игроков со всеми
семью стадиями, ещё 20 с четырьмя футбольными и все 80 исходных сотрудников с тремя
кадровыми стадиями. Все 44 доступных сравнительных страницы просмотрены; технический
аудит всех 5 780 вариантов прошёл. Остаётся 73 листа / 1 460 вариантов.
Imagegen сообщил сброс лимита 13 октября в 11:57:51 UTC / 13:57 по Белграду;
точный остаток сохранён в generation-checkpoint.json. Автопродолжение не настроено.

Листы созданы встроенным Imagegen в режиме сохранения личности исходных людей.
Python только нарезает целые бюсты, равномерно масштабирует, выделяет материал формы,
проверяет и создаёт превью. Старые PNG-комбинаторы сохранены как отклонённые эксперименты.

Каждая строка сравнений показывает одного человека во всех группах. Автоматический
аудит проверяет PNG, alpha, хеши, маски, цвета формы и неизменность пикселей вне одежды.
Рейтинг сходства с исходными двадцатью лицами помогает выбрать пары для просмотра;
он не доказывает ни смену личности, ни её сохранение. Возрастная седина и линии лица
могут существенно изменить такой рейтинг.

Назначение в PostgreSQL, резервирование внешностей, сезонный rollover, вторая карьера
и Telegram cache относятся к другим задачам. Новые комплекты лиг и молодёжные замены
потребуют пополнения банка людей; увеличение числа возрастных вариантов не увеличивает
ёмкость уникальных внешностей. Существующий банк переиспользуется для других людей без удаления истории.
