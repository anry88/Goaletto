# Локальная калибровка десяти сезонов · AND-150

`scripts/simulate_ten_seasons.py` — ускоренная симуляция реального мира 5×10,
с PostgreSQL и игровыми application services. `scripts/run_calibration_local.py`
запускает её рядом с **существующим** локальным PostgreSQL в Docker Desktop на Mac,
чтобы не тратить время на тысячи round trips через границу Mac/VM. Новая БД и
второй PostgreSQL не создаются. Это отдельный локальный процесс калибровки,
без Telegram polling, отправителя, публичного HTTP/API и изменений production.

## Запуск

Нужны текущие миграции единственной development БД `goaletto` на
`127.0.0.1:5433`, Docker Desktop `desktop-linux` и установленный проект/зависимости.
Launcher проверяет Compose project=goaletto, service=postgres и этот точный
loopback port binding; внутри app-контейнера используется только network namespace
проверенного PostgreSQL. Host-only файл с DB URL удаляется по окончании,
bot token не передаётся. `data_protection` запрещает сброс реальных данных.
Не запускать параллельно PG tests, worker или другую симуляцию на этой БД.

```bash
docker build --platform linux/arm64 --target runtime -t goaletto:calibration-local .
.venv/bin/alembic upgrade head
.venv/bin/python scripts/run_calibration_local.py --seasons 10 --seed 71 \
  --output work/calibration-10-seasons
```

На Intel Mac использовать native `linux/amd64` image. Прямой host-запуск:

```bash
.venv/bin/python scripts/simulate_ten_seasons.py --reset-local-development \
  --seasons 10 --seed 71 --output work/calibration-10-seasons
```

Сценарий намеренно **сбрасывает development-мир** перед новым запуском. Это не
команда для production: environment/driver/host/port/database проверяются до reset.
Session advisory lock исключает второй экземпляр симулятора. Не менять scope
для подключения production. Месяцы/годы проходят по явно заданным UTC датам, не wall clock.
Начальная дата2030-01-01, стартовый капитал600K — обычный игровой капитал, не грант.

## Стратегии и сравнение

Один seed задаёт мир; назначение стратегий клубам tier5 ротируется с seed.
Все клубы начинают с одинаковыми600K и сравнимыми baseline составами.

| Стратегия | Действия |
|---|---|
| bot | Обычный свободный клуб; никаких тренировок/покупок/управления |
| maintenance | Посещение клуба, базовый набор академии и недорогие замены при составе<18; фиксированная расстановка |
| lineup | То же содержание, подбор лучших здоровых по позициям и сохранение состава |
| academy | Улучшения при наличии денег и резерва, реальные наборы/бесплатные подписи, тренер защиты и тренировки |
| scout | Реальный найм скаута, одна оплаченная16-дневная миссия в сезон, подпись доступного кандидата при открытом окне |
| defence | Реальный найм защитного тренера, средняя интенсивность защиты в каждый доступный день |
| attack | Реальный найм тренера атаки, высокая интенсивность атаки в каждый доступный день |

Все человеческие клубы используют общую минимальную политику поддержания состава:
обычный базовый выпуск при дефиците и доступные публичные покупки до18 игроков.
Её расходы видны в ledger; это активный контроль содержания, а не полностью
бездействующий человек. Академическая стратегия совмещает развитие инфраструктуры,
подписание и обучение: её эффект нельзя приписать одному лишь уровню здания.
Скаут выбирает позицию слабейшего игрока, получает финальную shortlist, подписывает
по навыку/цене/доступному бюджету; числовой потенциал не используется для выбора.

Условия оплаты проходят обычные сервисы, бесплатно staff/скауты не выдаются.
Покупки оставляют денежный резерв; зарплаты, содержание, билеты, спонсор и призы
начисляются обычным finance runtime. При банкротстве управление прекращается;
нет нового гранта или бесплатного reclaim. Возраст, пенсия/вторая карьера,
пополнение ботов, сезонный спонсор, повышения/вылеты/турниры — настоящий rollover.

## Реальная и ускоренная часть

Каждый официальный матч получает обычные lock/start snapshots, recovery,
practice/development terms. Pure V4 engine проходит все тики/перерыв/ET/пенальти
сразу, finalizer сохраняет итог, участие, рост, энергию, деньги и следующий этап.
Другие задания (salary/training/scout/market/stadium/season.open) выполняются через
`process_one_job` с их due_at. Перед тренировкой учитываются условные планы кубков.
Rollover отказывается от любого незавершённого матча, результаты не придумываются.

Per-tick jobs/стадии/доставка, повторная материализация раз в час и world.reserve
не прогоняются wall-clock worker. Нужные горизонты планируются по UTC дням;
заменённые продолжения имеют явный held/done статус в disposable мире. Это
калибровка геймплея, не доказательство надёжности tick worker, live-команд или capacity.
Ускоренный finalizer получает приближённое время завершения: 33 минуты для
основного времени, 46 минут плюс число пенальти для ET. Для ET без пенальти это
на минуту консервативнее реального игрового clock; фактическое участие 0..120
минут считается движком. Прогон не измеряет точность live-таймингов.
Товарищеские основной мир автоматически не создаёт. Отдельный pure стресс даёт
слабому17-летнему с навыками3, caps20 и staff20 плотное участие/обучение без травм:
это верхняя граница роста, не сохранённые результаты или возможный бесплатный найм.

## Выход и инварианты

`summary.json`, `clubs.csv`, `report.md` и `players.json` в выбранном work каталоге.
История хранит людей до/после каждого сезона, навыки, дроби, caps и growth budgets.
Сводка содержит сезон/лигу/место/очки/голы, состав, средние навыки, академию, баланс,
виды ledger, принятые действия, платные подписи и причины отказов стратегии.
Проверяются1..20/caps, максимум25 игроков, training<=20000/match<=10000/
всего<=30000bps за возраст-сезон, <=15000bps на навык, реальные двухсезонные
дельты, сверка денежного ledger с балансом и повтор finalization без второго дохода.

Парные probes сравнивают лучший доступный XI с фиксированным начальным ботом:
одинаковые канонические match/player IDs, seed, home/away, возраст25, форма6,
мораль50 и полная энергия. Так сравнение отделяет навыки/выбор состава от
случайного календаря, текущей усталости и возраста. Матчи probes не идут в БД.
Это небольшая разведочная выборка, не статистическое доказательство превосходства
любой стратегии. Реальная таблица включает взаимодействие стратегий в одном мире,
старение/травмы/переходы и разные турнирные возможности. Один удачный seed или
среднее по всей скамейке не устанавливают хороший баланс.

После завершённой границы сезона возможен `--resume` **на той же БД и отчёте**.
Это не произвольное восстановление упавшего дня; при незавершённом сезоне нужен
новый development прогон. После завершения можно пересчитать все probes из
сохранённых снимков без повторных игровых сезонов:

```bash
.venv/bin/python scripts/run_calibration_local.py --resume --report-only \
  --seasons 10 --seed 71 --output work/calibration-10-seasons
```

При будущей калибровке использовать несколько seed и менять политику/коэффициенты
отдельным проверяемым изменением. Красный флаг или отсутствие преимущества в
результате нельзя заменять утверждением «всё сбалансировано».

Завершённый прогон: [10 сезонов / 6055 матчей, результаты и ограничения](reports/ten-seasons-2026-10-20.md).
