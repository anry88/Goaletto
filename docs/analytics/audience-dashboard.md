# Игроки и источники · Grafana

`goaletto-audience` в общей папке Goaletto operator показывает числом:
всех зарегистрировавшихся, новые регистрации и активных за24 часа /7 /30 дней,
получивших клуб за всё время, регистрации и активность по источнику первого входа.
Период по источникам выбирается вверху. Ссылка есть и в прежнем «Вход и участие».

Регистрация — первый принятый игровой `/start` (first_game_start_at / first-touch),
не создание строки Manager при preview и не каждый повтор /start. «Активный» —
уникальный менеджер с явным user_activity событием за выбранное скользящее окно,
независимо от даты регистрации. Автоматические матчи, доставки, ошибки и будущие
по recorded_at события не создают активность. Internal/opt-out исключаются.
«Получили клуб» означает наличие исторического ownership, а не только текущего.
Повторный start не меняет first-touch. При недоступной старой атрибуции источник
не подменяется direct: он unknown. Дата начала покрытия и неполнота длинных окон
показаны рядом с числами; история snapshots не выдаётся за прежнюю телеметрию.

## Данные и ограниченные метки

Новый read-only запрос инфраструктуры дополняет фоновый SQL-снимок. Семантика
замороженного goaletto_operator.report/0044 и старые отчёты не меняются.
`goaletto_audience{window,source,measure}` содержит только четыре фиксированных
окна, три меры и source=direct/unknown/other/c01..c32. Внутренние bucket IDs
не являются campaign/person IDs. Коды /start, имена, UUID и payloads не уходят
в Prometheus labels. Сверх32 источников числа складываются в «Другие источники».
Источник автоматически становится известным без предварительной регистрации.

Названия первых32 registry-источников по immutable created_at/id попадают только
в JSON native dashboard. Отдельный gauge-value fingerprint карты связывает
его queries с соответствующим SQL-снимком. Если operator добавил задним числом
кампанию и порядок изменился, старая история слотов не получает чужое название:
несовпадающий fingerprint скрывает эти samples. При добавлении источника обычным
путём worker обновляет и числа, и названия без ручной правки Grafana.

Все числовые панели используют существующий `goaletto-vm`, success и свежесть120s.
Нет SQL datasource, внешнего API или Grafana admin credential в приложении.
На scrape БД не читается. Ошибка SQL очищает старые families; пустое наблюдаемое
значение не превращается в успешный ноль. Реально измеренное отсутствие —0.

## Публикация

Опциональный GOALETTO_METRICS_DASHBOARD_PATH включает публикацию только worker.
После snapshot отдельная bounded READ ONLY transaction получает map/coverage;
временный файл атомарно заменяет audience.json только при изменении содержимого.
Обычный Grafana file provisioning подхватывает его без перезапуска Grafana.
Сбой публикации ограничен своим timeout и не отменяет game commits или метрики.
Числа не встраиваются в JSON: названия и оформление отделены от VictoriaMetrics.

HDC добавляет `deploy/compose.audience.yaml` **после** прежних шести Compose-файлов.
GOALETTO_AUDIENCE_DASHBOARD_DIR указывает на отдельный подкаталог audience в
существующем Grafana Goaletto provisioning tree. Worker имеет RW только к этому
новому подкаталогу; соседние dashboards, datasource/секреты и PGDATA не монтируются.
Для новой папки тому же Docker-пользователю нужен доступ Modify; он не даёт доступ
к другим файлам или учётным данным. monitoring и data-d overlays сохраняются.
Локально опция выключена. Никогда не запускать дополнительный poller ради dashboard.

Проверки: ручная SQL-матрица на временных таблицах единственной локальной
application DB (transaction rollback), регистрация/активность/дедупликация,
internal/opt-out/system/late exclusions, bounded labels, mapping fingerprint,
атомарная публикация/повтор/новый источник. Новый DB/migration не требуются.
