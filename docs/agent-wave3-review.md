## Исправления при review

Диагностика использовала произвольную историческую ставку для определения
занятости покупателя. Теперь берётся именно `highest_bid_id`, с проверкой
принадлежности аукциону. Нормальная отсрочка подтверждается только полным
снимком. При `--season` денежные резервы остаются глобальными, но наличие
market.close и занятость клубов нельзя доказать ограниченным календарём:
выводится `MARKET_SCHEDULE_SCOPE_LIMITED`, без ложного сигнала пропавшей задачи.

Recovery проверяется против сохранённых хешей checkpoint tick/stage; для
границы 15 допустимы halftime tick и second-half stage. Следующая job должна
иметь точное время, вид и номер тика. Добавлены unit regression и настоящий
PG-кейс с намеренной порчей хеша в синтетическом наборе данных.

В аналитическом PG fixture ожидались восемь попыток доставки, а создавались
семь. Добавлена предусмотренная матрицей попытка `duplicate`; строгое ожидание
сохранено. Тесты не изображают готовыми ещё отсутствующие метрики.

В offline CLI официальные победы, ничьи и голы теперь считаются только по
завершённым матчам; частичные голы прерванных матчей показаны отдельно.
Replay сравнивает полные события и accepted/rejected commands, а не только
идентификаторы. Пустые сценарии/сиды и чрезмерный бюджет отклоняются до
выделения памяти под диапазон. Оба новых script проходят отдельный mypy.

Backup перед dump read-only проверяет фактическое имя базы, версию сервера и
таблицы Goaletto. Публикация hard link запрещает перезапись при гонке;
`--overwrite` отклоняется. Ошибка второй публикации удаляет только свой файл,
сохраняя чужие архивы. Проверяются размер, custom header, безопасное имя
архива и SHA256. Raw stdout версии и stderr не попадают в manifest/ошибки.
Manifest публикуется последним как признак готовности. Атомарность пары при
аварийном завершении процесса и fsync durability не обещаются.
