# Часовой пояс и удобное время · AND-120

В `/settings` доступны выбор пояса и инструкция `/kickoff 19:30`.
Уточнение владельца 2026-10-20 ([AND-144](ui-feedback-2026-10-20.md)):
`/timezone` показывает все целые смещения UTC−12…UTC+14, включая UTC,
вместо поиска города. Кнопки `UTC+1 (10:02)` показывают местное время при
открытии списка; есть обновление. Нажатие явно сохраняет фиксированный пояс
без сезонного перевода. В БД — `UTC` / IANA `Etc/GMT` с корректным обратным
знаком; интерфейс показывает UTC offset. Существующий городской пояс остаётся
до явного выбора; устаревший city callback открывает новый список без записи.
`/kickoff HH:MM` явно сохраняет местное предпочтение, включая минуты,
не кратные 30. По умолчанию пояс UTC, предпочтение отсутствует и используется
18:00 UTC. Смена пояса сохраняет выбранные местные часы.

Миграция 0023 добавляет поля менеджера, receipts изменений и решений расписания.
Повторы старого update/callback после более новой настройки ничего не откатывают;
повтор operation ID с другими параметрами отклоняется. Изменения не продлевают
владение и не меняют назначенные встречи/jobs. Язык Telegram не выбирает пояс.
В `/match` время ближайшей встречи и закрытия состава отображаются в поясе
менеджера; уведомление о восстановлении live-матча также использует пояс адресата.
Если местная дата отличается, рядом указана дата UTC игрового дня.

`choose_kickoff` — чистый расчёт на дату встречи с zoneinfo. Runtime включает
[tzdata](https://pypi.org/project/tzdata/), чтобы IANA-пояса были доступны также
на Windows и в контейнере без системного справочника:


- Против бота используются точные местные часы человека, включая смещения
  UTC на 15/45 минут. Два бота используют 18:00 UTC. Человек без предпочтения
  использует 18:00 UTC; если другой человек выбрал часы, рассчитывается среднее.
- Два человеческих предпочтения переводятся в UTC на дату встречи, затем берётся
  середина кратчайшей дуги часов. 23:00/01:00 → 00:00; 14:00/16:00 → 15:00;
  14:00/15:00 → 14:30. Результат округляется к ближайшему получасу; ровно
  15 минут округляются вперёд по UTC-часам, включая переход 23:45 → 00:00.
- При разнице ровно 12 часов отсортированные часы и `seed % 2` выбирают одну
  из двух середин симметрично относительно хозяев/гостей. Seed, результат,
  версия и tie-break сохраняются в `kickoff_decision_receipts`.
- Для повторяющихся местных часов осенью выбирается раннее UTC-вхождение;
  несуществующие часы весной сдвигаются вперёд на размер DST-разрыва.
  Поиск соседних местных дат удерживает kickoff внутри заданных UTC-суток
  даже для UTC+14/UTC−12. Выбор местной даты не меняет турнирный день.

`fixture_kickoff_decision` атомарно читает действующих владельцев/настройки и
сохраняет решение по ключу запланированной встречи. Параллельный расчёт и retry
возвращают то же время даже после смены владельца/настроек. Изменение участников,
даты или seed под тем же ключом отклоняется. Caller должен использовать стабильный
seed встречи и вызывать сервис при входе встречи в горизонт объявления.

[Планировщик AND-121](four-day-calendar.md) реализован: вызывает сервис при
входе встречи в 10-дневный горизонт и создаёт jobs из сохранённого времени.
Старый тестовый мир пересоздан; совместимость с weekly-v1 не поддерживается.

Проверки: все получасовые пары и симметрия сторон; дробные/крайние UTC offsets;
DST зима/лето/gap/fold для существующих IANA preferences; все 27 новых fixed
offsets, обратный знак Etc/GMT, полночь/валидация; rollback, параллельные решения и receipts
в единственной Goaletto DB; настоящий Telegram dispatcher с fake transport.
