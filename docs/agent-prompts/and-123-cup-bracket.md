# AND-123 · чистая структура кубка 50 клубов

Работаешь над Goaletto: Python/Telegram, без JavaScript, Mini App и нового API.
Начни с последнего origin/main, отдельная ветка codex/; базовая готовая сборка
84ef78528b7d6e743bfc5792869652a38cbddf0a или новее. Прочитай AGENTS.md, README.md,
docs/game-rules.md, football-manager-bot-gdd.md и docs/calendar-cups-update-2026-10-14.md.
Правила пользователя важнее старых примеров. Сезон 18×4 дня + 8 дней межсезонья.
День 3 — добровольное окно: тренировка, товарищеская игра или отдых; без заявки
менеджера ничего не назначается. Тренировки разрешены в любой свободный UTC-день.

Это независимый чистый расчёт, часть большой задачи, а не её полная реализация.
Не меняй ORM, миграции, bot/application/worker, существующий match state, ledger,
портреты и общий en.json. Интеграцию, durable snapshots/receipts и общую БД ведёт Codex.
Не подключай БД и не запускай integration/reset; создавать новые тестовые БД нельзя.
Domain без aiogram/SQLAlchemy/сети/wall clock и unseeded RNG. Явные входные данные,
версия policy, seed, неизменяемые результаты. Сохраняй чужие изменения. Не вливай
самостоятельно в main: передай commit/patch для review и интеграции Codex; публикация
общего main выполняется после неё. Не отмечай всю родительскую задачу Done.

Реализуй src/goaletto/domain/cup_bracket.py и tests/unit/test_cup_bracket.py.
Не трогай domain/league_allocation.py: параллельно работает другой исполнитель.

Вход: season/group ID, seed, immutable membership пяти лиг tier 1..5 по десять
уникальных клубов и frozen entry order. Для первого сезона entry order приходит
из сохранённого стартового жребия/tie_break_order: не выдумывай прошлые результаты.
Для следующих это явно переданная завершённая таблица. API строит dependency graph
противостояний с устойчивыми IDs, участником club ID либо winner(tie ID), номером
кубкового дня/цикла, двумя legs с обменом поля, одиночным нейтральным финалом.

Дни 1–2: нижние 8 tier5→4. Дни 3–4: добавить верхние 2 tier5 и 10 tier4,
всего 16→8. Дни 5–6:8→4;7–8:4→2. Дни 9–10: добавить 30 tier1..3,
всего32→16. Дни11–12:16→8;13–14:8→4;15–16:4→2;день17:финал.
День18 резерв, без автоматического матча. Итого49 ties,97 matches,50 уникальных
участников, один победитель, каждый enters ровно однажды, максимальный путь17 игр.
Жребий seeded/versioned, независим от порядка input. Не пересчитывай entry rank
из текущей таблицы. Сетка не привязывает будущие переходы к старой лестнице.

Дай pure функцию разрешения слота/продвижения при переданных окончательных winners
и вычисления возможных club IDs для будущих слотов: после вылета убрать клуб из
зависимых ветвей, сохранив другую ветвь. Несовместимые результаты, цикл зависимостей,
дубликат/чужой победитель — ошибка. Не симулируй ET/pens и не принимай ничью за winner:
окончательного победителя позже передаст общий knockout runtime AND-124.
Не назначай точные kickoff/jobs: их материализует Codex в горизонте десяти дней.

Проверки: полный прогон сетки, разные seeded winners, все входы/дни/числа,
home/away exchange, стабильные IDs/replay/input permutation, conditional possible IDs
до/после вылета, некорректные inputs и отсутствие лишнего матча в резервный день.

Передача: commit/patch, список файлов, публичные signatures и пример вызова,
ruff check/format, mypy и релевантные unit pytest с результатами. Перечисли
оставшуюся интеграцию и риски. Не отправляй реальные Telegram-сообщения и не делай deploy.
