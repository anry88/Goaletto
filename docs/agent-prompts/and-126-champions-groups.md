# AND-126 · чистые отбор и группировка Кубков чемпионов

Работаешь над Goaletto: Python и Telegram, без JavaScript, Mini App и нового API.
Начни с последнего origin/main, содержащего 85555275740efaf545fa7d0042f2a5831dee7541
или более новую приёмку. Создай отдельную ветку codex/and-126-champions-groups.
Прочитай AGENTS.md, README.md, docs/game-rules.md, football-manager-bot-gdd.md,
docs/calendar-cups-update-2026-10-14.md и docs/tournament-domain.md.
Требования пользователя важнее архивного GDD.

Это независимый вычислительный подпакет AND-126, а не весь турнир.
Разрешены только новые файлы:
- src/goaletto/domain/champions_groups.py;
- tests/unit/test_champions_groups.py;
- docs/champions-groups-domain.md — контракт и точки подключения.

Не меняй cup_bracket.py, league_allocation.py, neutral_final.py, knockout.py,
существующий матчевый движок, ORM, миграции, application, bot, worker, en.json,
зависимости или pyproject.toml. Другие агенты делают knockout rules и баланс.
Не подключай БД, не создавай тестовых БД и не запускай integration/reset.
Domain без aiogram/SQLAlchemy, сети, часов и unseeded RNG. Явный seed, versioned
policy, immutable входы/результаты. Сохраняй чужие изменения. Передай commit/patch
для review Codex; самостоятельно не вливай/не публикуй main и не закрывай всю AND-126.
Не отправляй Telegram-сообщения, не делай deploy и не запускай других агентов.

Вход: явный ключ совместимого qualifying cohort, снимки завершённых сезонов,
league/set/season IDs, qualifying tier и frozen порядок десяти club IDs каждой
лиги, seed. Совместимость дат и завершение турниров проверяет orchestration.
Внутри комплекта одна полная вертикаль tier 1..5 и один qualifying season;
один season ID не может принадлежать разным комплектам. Дубликаты клубов/лиг,
неполные вертикали, mixed cohort keys и неверные числа/UUID отклоняются.
Можно переиспользовать LeagueSnapshot чтением/import, если его семантика подходит;
не меняй его или другие общие типы ради своего API.

Для каждого tier 1..5 отбираются верхние восемь клубов каждой лиги. Девятое и
десятое места не участвуют. Уровни не смешиваются. Qualifying tier/season остаются
в результате: повышение или понижение после отбора не меняет допуск задним числом.
Текущие владельцы и актуальная таблица не являются входом повторного draw.

Реализуй предложенную в AND-126 группировку совместимых комплектов по степеням
двух, максимум 64 комплекта в одной группе. При N=1/2/3/4 получаются 1;2;2+1;4.
Дополнительные случаи: 6→4+2, 7→4+2+1, 65→64+1. При большем N допускаются несколько
групп по 64 и остаток. Каждый комплект входит ровно в одну группу каждого уровня,
каждый отобранный клуб — в один турнир своего qualifying tier.

Распределение комплектов seeded, воспроизводимо и независимо от порядка входа.
Не закрепляй постоянно первые UUID в большой группе: сортировка нужна только
для детерминированной базы перед жребием. Жребий групп каждого уровня имеет
явный отдельный ключ; перечисли, что именно нужно сохранить для replay.
Группы и участники получают устойчивые IDs в namespace cohort/policy/tier.
Ни время job, ни вызов random без seed не должны влиять на результат.

Для группы G верни 8G участников, число раундов log2(8G) и число матчевых дней
2*log2(8G)-1: G=1/2/4/8/16/32/64 → 5/7/9/11/13/15/17.
Верни структурные номера champions cycles начиная с 1 и свободные циклы до 18;
фаза каждого такого дня — день 2 четырёхдневного цикла. До финала два матча,
финал одиночный нейтральный. Не строй второй общий knockout engine и не меняй
50-клубную сетку, которая имеет другой staged-entry формат. Подробная сетка,
ET/пенальти, venue и фактический kickoff/jobs остаются центральной интеграции.

Первый сезон без прошлой таблицы и новый комплект посреди сезона не должны
получать выдуманные qualifying results. API работает только с явно переданным
полным завершённым cohort; отсутствие таких данных отклоняется/явно обозначается
как отсутствие отбора, а не заполняется случайными клубами. Bootstrap policy
остаётся отдельным решением перед включением турнира, опиши это в документации.

Проверки: 1/2/3/4/6/7/64/65 комплектов, дополнительный случай N>128; пять tiers,
по восемь участников из каждой лиги, отсутствие дублей/потерь, размеры групп,
правильные 5..17 дней, свободный 18-й цикл, stable IDs/replay/input permutation,
разные seeded составы групп и неправильные/неполные snapshots. Проверяй смысл
жребия и сохранение участия, не только конкретную сортировку UUID.

Передача: commit SHA/patch, список файлов, публичные signatures и пример,
ruff check/format, mypy, релевантные unit pytest. Перечисли оставшееся:
bootstrap, выбор совместимых сезонов, persisted eligibility/groups/draw receipts,
сетка, fixtures/jobs в горизонте десяти дней, общий knockout runtime, выплаты/UI.
