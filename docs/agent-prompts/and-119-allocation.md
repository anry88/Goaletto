# AND-119 · чистое распределение переходов

Работаешь над Goaletto: Python/Telegram, без JavaScript, Mini App и нового API.
Начни с последнего origin/main, отдельная ветка codex/; базовая готовая сборка
84ef78528b7d6e743bfc5792869652a38cbddf0a или новее. Прочитай AGENTS.md, README.md,
docs/game-rules.md, football-manager-bot-gdd.md и docs/calendar-cups-update-2026-10-14.md.
Правила пользователя важнее старых примеров. Сезон 18×4 дня + 8 дней межсезонья.
День 3 — добровольное окно: тренировка, товарищеская игра или отдых; без заявки
менеджера ничего не назначается. Тренировки разрешены в любой свободный UTC-день.

Это независимый чистый расчёт, часть большой задачи, а не её полная реализация.
Не меняй ORM, миграции, bot/application/worker, существующий match state, ledger,
портреты и общий en.json. Интеграцию, durable snapshots/receipts и общую БД ведёт Codex.
Не подключай БД и не запускай integration/reset; создавать новые тестовые БД нельзя.
Domain без aiogram/SQLAlchemy/сети/wall clock и unseeded RNG. Явные входные данные,
версия policy, seed, неизменяемые результаты. Сохраняй чужие изменения. Не вливай
самостоятельно в main: передай commit/patch для review и интеграции Codex; публикация
общего main выполняется после неё. Не отмечай всю родительскую задачу Done.

Реализуй src/goaletto/domain/league_allocation.py и tests/unit/test_league_allocation.py.
Изучи src/goaletto/domain/leagues.py, application/season_rollover.py,
docs/season-rollover.md и docs/season-sponsorship.md только для контекста.

Вход: неизменяемые снимки совместимого завершённого cohort, идентификаторы сезонов,
лиг, tier и frozen итоговый порядок десяти уникальных club IDs каждой лиги, seed.
Совместимость cohort проверяет orchestration Codex; pure API обязан отклонять
неполные/дублированные снимки, смешанные cohort keys и неполные вертикали tier 1..5.
Предложи небольшие typed dataclasses и одну функцию allocate(...), опиши контракт.
Все 2 верхних/2 нижних переходят одновременно в соответствующий соседний tier;
1 не повышается, 5 не понижается. Оставшиеся сохраняют свою лигу. Отдельно перемешай
promoted/relegated pools и соответствующие вакансии: по два входящих от каждого
применимого соседнего уровня, ровно десять в каждой лиге. League set не фиксирует
маршрут; клубы одной исходной лиги могут попасть в разные новые лиги. Ни один клуб
не проходит два перехода. Результат club→destination league и проверяемая draw
структура детерминированны для seed и не зависят от порядка входа или времени job.
Снимок пригоден для будущего persisted receipt; не добавляй сохранение сам.
Не меняй возраст, назначения staff, last-season IDs и спонсорские условия:
результат передаёт destination tier/league, жизненный цикл подключит Codex один раз.

Проверки: 1/2/3/4 комплектов и разные seed, по десять в лиге, сохранение всех clubs,
правильный tier, неподвижность оставшихся, воспроизводимость при перестановке входа,
возможность межкомплектного распределения без flaky probabilistic assertion,
повреждённый/несовместимый input. Не заменяй тесты проверкой точной сортировки UUID.

Передача: commit/patch, список файлов, публичные signatures и пример вызова,
ruff check/format, mypy и релевантные unit pytest с результатами. Перечисли
оставшуюся интеграцию и риски. Не отправляй реальные Telegram-сообщения и не делай deploy.
