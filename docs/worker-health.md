# Работоспособность worker · AND-70

`python -m goaletto.diagnostics.health_cli` читает PostgreSQL и проверяет
**текущий экземпляр** worker. Exit 0 — оба необходимых цикла работают, exit 1 —
проверка не прошла или данные недоступны. Вывод — короткий JSON без токенов,
DSN, Telegram ID, текстов сообщений и индивидуальных игровых ссылок.
HTTP endpoint и публичный API не добавляются.

## Что считается работой

Миграция 0043 добавляет operational `worker_heartbeats`: boot UUID, компонент
`jobs` / `sender`, начало, последнее наблюдение, последний успешный проход,
статус `starting` / `ok` / `error`. Каждая загрузка worker получает новый UUID.
Он записывается атомарно в закрытый файл экземпляра, по умолчанию
`/tmp/goaletto-worker-instance` внутри Linux-контейнера.
`GOALETTO_WORKER_HEALTH_FILE` позволяет задать другой путь; родительский каталог
должен существовать и быть доступен на запись. Несколько локальных процессов
на одной файловой системе используют разные пути. Контейнеры имеют отдельный `/tmp`.

Отметка обновляется **после возврата commit** игровой итерации, включая
нормальную пустую очередь. Отдельная heartbeat-транзакция ограничена одной
секундой и не может отменить уже сохранённый игровой эффект. Успешные записи
делаются не чаще раза в 10 секунд, ошибки отмечаются сразу. Если сама запись
недоступна, здоровье постепенно становится stale, успех не выдумывается.
При долгом зависании обработки нет отдельного фонового таймера, который бы
продолжал объявлять worker исправным.

При Telegram 429 sender намеренно ждёт, проверяя своё ожидание каждые 10 секунд;
это поддерживает liveness, но не повторяет сетевой запрос раньше retry_after.
Ошибка цикла не превращается в успешное ожидание. Sender проверяется отдельно
и обязателен только при `GOALETTO_OUTBOX_ENABLED=true`.

Пустая очередь не означает остановку worker; успешный проход sender не означает
доставку сообщения. Конечные ошибки заданий и неизвестные исходы Telegram
отдельно видны в [диагностике](runtime-diagnostics-runbook.md) и
[операционных отчётах](runtime-observation.md).

## Состояния

- `ok`: есть свежий успешный проход данного экземпляра.
- `starting` / `missing`: цикл ещё не подтвердил работу или запись отсутствует.
- `error`: последняя наблюдаемая итерация завершилась исключением.
- `stale`: более 120 секунд без свежего наблюдения/успешного прогресса.
- `unknown` / `invalid_clock`: наблюдения неполны либо часы противоречат данным.

`--max-age-seconds 30..900` меняет порог явно. Другой исправный экземпляр не
скрывает отказ текущего. Старые boot-записи старше семи дней удаляются при
следующем запуске. Это disposable мониторинг, не игровая история: downgrade
0043 может удалить heartbeat-таблицу, не изменяя матчи, ledger или аналитику.
Рестарт начинает с `starting`, не заимствует старый успех. Ошибка подготовки
worker закрывает bot session и DB pool до выхода.

## Docker и действия оператора

В `compose.yaml` worker получил healthcheck: интервал 30 секунд, timeout 8,
три неудачные проверки и стартовый период 30 секунд. Его наследует release
override. `restart: unless-stopped` сохранён. Docker healthcheck сам по себе
не перезапускает зависший живой процесс; состояние unhealthy нужно подключить
к существующему мониторингу production. Отдельный autorestart/watchdog не включался.

```bash
python -m goaletto.diagnostics.health_cli
```

Если unhealthy: проверить DB и файл текущего экземпляра, затем возраст обоих
циклов, jobs/outbox и runtime diagnostics. Перед перезапуском сохранить
наблюдения; не сбрасывать pending/failed jobs и не объявлять unknown send
доставленным. После восстановления соединения пул переподключается, цикл
снова подтверждает успешный commit. Технические heartbeat-записи никогда
не продлевают владение, пользовательскую сессию или retention.

production deployment, off-host daily backup и подключение тревог остаются этапами
AND-69/70/72. Наличие локального healthcheck не подтверждает их выполнение.

Семантика Docker: [HEALTHCHECK](https://docs.docker.com/reference/dockerfile/#healthcheck)
и [restart policies](https://docs.docker.com/engine/containers/start-containers-automatically/).
